# 衣橱版本记录

产品现为 **v1.0.13**。当前能做什么、代码怎么放，见 [docs/current-state.md](../docs/current-state.md)。不能破坏的行为见 [docs/invariants.md](../docs/invariants.md)。

下面按时间记下每一版做了什么，以及当时明确不做的事。

## v1.0.1 桌面先行（2026-09-16）

Flutter Windows 桌面端。本地 SQLite 和图片，仓储层预留同步接口，不接账号和云。左侧导航是衣橱、穿搭、日历，没有「我的」。

- 衣橱：默认分类网格，单品增删改，尺码模板随分类切换
- 穿搭：场合分类网格，一张图加元数据，分类当时写在代码里
- 日历：月历壳和农历，不写入穿着

当时明确不做：会员和分享、「我的」、拍照或批量加图、穿搭画布、日历穿着记录、云同步、手机布局。

## v1.0.2 排序与单品详情（2026-09-16）

- 列表排序：添加、购买、修改时间、价格；穿搭只有添加和修改。默认「添加时间 · 新→旧」
- 分类封面改为该分类 `createdAt` 最新一件，不跟列表排序走
- 点缩略图进只读详情，再进入修改；保存后回到详情
- 路由拆成详情和编辑

当时明确不做：排序条件写到磁盘、详情页里直接删除、云同步、日历写入、穿搭画布。

## v1.0.3 衣橱分类树（2026-09-16）

- 分类入库。首页去掉排序，改为「分类管理」。搜索仍按添加时间新→旧
- 大分类下最多两层小分类。封面和件数按子树
- 单品用完整路径选分类，尺码模板取根大分类
- 「无分类」可改名、排序，不能删

当时空分类会跳到添加，删除一律回到无分类。这两点在 v1.0.4 改掉。当时也不做穿搭分类树、分类拖拽、云同步。

## v1.0.4 分类细化（2026-09-16）

- 删除有上级的子分类时，衣物回到直接上一级；只有删大分类才回无分类。确认弹窗写出实际去向
- 空分类也进详情。还能再分一层时，可添加子分类，并勾选本层衣物一并移入
- 每一级独立封面。同一件可以当祖先分类和自己所属分类的封面，不能当旁系封面
- 详情顶栏「移动」，弹出整棵分类树。封面图上不放移入、移出
- 同一层名称不能重复；不同父分类下可以同名。已有的同名分类不自动改名
- 包包、配饰：分类管理里的模板叫「物件」，表单测量项叫「尺寸」

当时明确不做：穿搭分类树、分类拖拽、云同步。

## v1.0.5 穿搭分类树（2026-09-20）

场合分类写入同一张 `categories` 表，`kind = outfit`（schema 4）。种子仍是无分类、工作、休闲、派对、运动、度假。

- 穿搭首页改为「分类管理」。浏览、封面、移动、同级不重名、删除回上级，与衣橱同一套规则
- 新增大分类不出现测量模板，也不抄衣橱的尺码字段
- 编辑页用完整路径选分类

当时明确不做：分类拖拽、云同步、日历写入。

## v1.0.6 衣物多图与抠图取色（2026-09-20）

同一件衣物可以有多张图。本地 U²-Net-p 抠图，从 Mask 取前景颜色，人工确认后保存。列表封面仍用 `clothing_items.imagePath`。

当时明确不做：衣服类型分类、吊牌 OCR。

## v1.0.7 图片工作室与精修（2026-09-21）

新增和修改衣物时，先在图片工作室处理照片，再填字段。库升到 schema 5。

- 选图可多选。长边不超过 1600，EXIF 转正，原图整张保留
- 加图只缩放，不自动跑 U²-Net。工作室「重新处理」才用 U²-Net-p
- MobileSAM 点选定外形：左键衣服、右键衣架。笔擦可保护衣服色。取样后再涂抹填补
- 颜色只统计 Mask 内像素。颜色栏为空时填入，已有内容只给建议
- 抠图失败则保留原图，不挡保存。新图角色一律是衣物照

当时明确不做：吊牌 OCR、衣服类型分类、添加流程里的「衣物 / 吊牌」切换。

## v1.0.8 吊牌照与 RapidOCR（2026-09-21）

工作室可以另加吊牌照。点选去掉背景后，本机 PP-OCRv4 识别文字。库升到 schema 6，`ocrJson` 存原文和解析出的品牌、面料、尺码。

- 吊牌不能当封面，也不参与后来的穿搭拼图
- 空字段才建议填入；已填内容不覆盖
- 不接云 OCR、Python 或 Flutter OCR 插件

当时明确不做：用吊牌当分类封面、自动改类别或款式、穿搭板块。

## v1.0.9 穿搭拼图与日历（2026-09-23）

穿搭可以关联衣橱里的衣物，用点选抠图手动拼封面，也可以上传全身照。日历按日期记日程、挂多套穿搭。库到 schema 9：schema 7 是穿搭原图和 `outfit_items`，schema 8 是日程和当日穿搭，schema 9 是 `coverMode` 与 `collageLayout`。

- 向导顺序是关联衣物、OOTD、详情。新建从第一步开始，修改已有穿搭从详情进入
- OOTD 页左边全身照，右边拼图。画布固定 3:4。拖动只命中抠图的不透明像素，滚轮缩放
- 封面自选：有全身照也可以用拼图。详情两张都显示，各自可删
- 空布局字符串表示用户删过拼图，和「还没摆过」区分开
- 日历日程从空列表点加号添加。同一天可挂多套穿搭，同一套一天只出现一次
- 天气按日期算出来，标「虚拟」，不入库、不联网
- 已发出的 schema 1–9 仍是手写升级，不改写成生成步骤。快照从版本 9 起

当时明确不做：真实天气、联网、把 1–9 重写成快照步骤、用吊牌照拼进穿搭、云同步。

## v1.0.10 验收收尾（2026-09-23）

工程计划四个阶段落地后，按 Codex 验收报告补了下面几处。能做什么与 v1.0.9 相同。

- 删除穿搭时，先等数据库删除成功，再回滚未提交的新图，最后才结束这次编辑。数据库删除失败时，新选的图片留到编辑器关闭再清掉。
- 拼图的 x/y/w/h 按画布上的实际位置保存和读回，超出 0..1 的位置也会原样恢复。
- 去掉全身照时，只有拼图布局是非空字符串，封面才切到拼图。还没摆过，以及用户删掉拼图后的空字符串，都保持原封面。
- 多件衣物共用同一个图片文件时，要等没有任何衣物再引用这个文件，才会删除。
- 是否在编辑已有穿搭，由控制器根据这套穿搭的编号判断。

`dart format lib test` 已执行。`git diff --check` 通过。`flutter analyze` 无问题，`flutter test` 89 项通过，`flutter build windows --debug` 已生成 `build\windows\x64\runner\Debug\wardrobe.exe`。

当时明确不做：继续扩大重构、改 schema、重开四个阶段。

## v1.0.11 设置页外观（2026-09-24）

侧栏底部的字体按钮改为设置。设置页第一块是外观：字体、文字大小、主体颜色。选择写在 `%APPDATA%\wardrobe\appearance.json`，没有这份文件时沿用已有的 `font.txt`。

主体色跟到主题和原先写死主色的页面。背景、文字、边框仍是原来的中性色。不新建 `lib/ui`。

字体五款里，「微软雅黑」是 `Microsoft YaHei`，不是 UI 版。等线没有「橱」，缺字只从微软雅黑补，避免落到宋体，也避免和 UI 版混用后这个字小一号。以前存成 `Microsoft YaHei UI` 的选择，读入时改成 `Microsoft YaHei`。

当时明确不做：自定义取色、深色模式、把列表排序写进设置、改数据库。

## v1.0.12 分类拖拽排序（2026-09-24）

分类管理里，同一层的上移、下移改成拖动手柄排序。衣橱和穿搭共用这一页。拖到同一父分类的另一行时，按落点在该行上半或下半，插到它前面或后面。子分类留在原来的父分类下，整支跟着父分类的新位置走。落到别的父分类上不会改父子关系。

顺序写回 `categories.sort_order`，不改表结构。拖动手柄上的「拖动排序」提示单独放在一层语义节点里，避免 Windows 无障碍树在滚动列表里把这个提示吞掉后反复打引擎日志。

当时明确不做：拖到别的分类下面变成它的子分类、分类拖拽改父级、改数据库。

## v1.0.13 衣物详情字段（2026-09-24）

衣物详情和编辑按 [design/item-detail.pen](../design/item-detail.pen) 重排。以后改这页的版式，先改这份 Pencil 稿。

品名单独一行，空着时详情标题仍是「单品详情」。列表上如果还没有品名，暂时显示以前的类别，再没有才显示「未命名」或分类名。分类只显示所在目录，改目录仍用移动和编辑页的分类选择。尺码是号型，例如 `175/92A`。颜色单独一行。面料和季节同一行。品牌单独一行。其后是价格和购入时间、尺码测量、存放位置、标签、备注、吊牌原文。

款式按版型、袖长、领型、结构点选，可以同时选多个。以前手写的款式如果对不上这些选项，仍保留，可以再点掉。洗涤维护分洗涤、漂白、干燥、熨烫、专业护理五组，点一下加入，再点取消，每一组通常只留一个，不从吊牌识别填入。两组都是白卡片里的圆角标签：选中是浅色底、没有边框；没选中有一圈细边。洗涤的组和标签前有对应图标。

页面不再显示类别和购买信息，这两列仍留在库里。新品名、号型、洗涤选择写入 schema 10：`product_name`、`size_code`、`care_json`。款式仍写在原来的 `style` 列。

分类详情里添加子分类时，名称输入框的控制器跟对话框一起销毁，避免关闭动画还在用已经销毁的控制器。

当时明确不做：吊牌原文按行修改、合并和删除，以及识别文字的自动矫正。
