# 工程计划 v1.0.14

仍是本地 Windows，不联网，不加账号。v1.1 再做云端存储适配，v1.2 再做 Android / iOS 的设计。只在 Windows 上用的完整版本收到 [plan_v1.0.15.md](plan_v1.0.15.md)。

库已经是 schema 11。这一版不再升 schema。详情布局已经落地，这一版不改它的排序、隐藏和并排规则。

## 查找

衣橱首页和分类页用同一套规则找衣服。范围是详情布局里开着的这些字段，再加上以前的类别：品名、号型、款式、颜色、面料、季节、品牌、洗涤选项上的中文、存放位置、标签、备注、所在分类，以及开着的自定义字段。

关掉的字段不参与查找。内容仍留在衣服上。以前的类别没有出现在布局里，但列表在没有品名时还会显示它，所以始终参与查找。

洗涤按选项上的中文匹配，不按内部编号。搜「手洗」能找到选了手洗的衣服。自定义字段也按页面上的文字：一行文字的内容，单选和多选里选中的选项。不按内部编号。

价格、购入时间、尺码测量、吊牌原文不参与查找。

## 排序

衣橱分类列表和穿搭分类列表各自记住上次的排序。写在 `%APPDATA%\wardrobe\`，和 `appearance.json`、`detail_layout.json` 分开，不放进设置页。没有这份记录，或读到不认识的值时，仍是「添加时间、新的在前」。

## 详情里删除

衣物详情可以直接删除，不必先进入编辑。确认文案和编辑页相同：「删除这件衣物？」「删除后无法恢复。」确认后走现有的删除，再离开详情。

## 吊牌原文按行改

识别结果已经按行存在这张吊牌照的 `ocrJson.lines`。布局里「吊牌原文」开着时，编辑页先只读展示原文，标题旁有「修改」。点进去才逐行改。这一页不另做路由：原文还在编辑页内存里的吊牌照上，写入数据库仍是编辑页的「确定」。字段关掉时，编辑页不列出这些行，已存的行不动。

对照页左边一半是当前吊牌图，右边是文字。不止一张时在顶上切换。鼠标停在一行上，行尾才出现上箭头、下箭头和叉，分别是并到上一行、并到下一行、删除。Enter 在光标处把这一行拆成两行。空行不保留。其余行，包括条码，只有用户删掉才消失。

改行只换 `lines`，不回写品牌、面料、号型，也不覆盖已经填过的字段。顶栏「重新识别」先确认会盖掉已改过的原文，确认后整份替换这一张的识别结果。不自动改正错字。

详情页仍只读，显示保存后的原文。字段关掉时，详情里也不出现。
