## 现状（为什么改一条会跑顺序）

衣物列表来自 `ItemRepository.watchAll()`，固定：

```dart
..orderBy([(t) => OrderingTerm.desc(t.updatedAt)])
```

保存时会刷新 `updatedAt`，所以「改备注」等于「排到第一」。分类封面也用这个顺序的第一张图，编辑也会换封面。

点照片走 `/wardrobe/item/:id`，直接进 `ItemEditPage`，没有只读详情。

## 1. 排序

右上角筛选按钮从占位改成**始终可见的当前排序**（你选了「不藏默认，让用户自己选」）。第一次打开列表时，控件上就写着某一项，避免空白。

**控件文案初始显示：`添加时间 · 新→旧`**（这样改内容不会跳位）。用户随时换。

可选：

| 选项 | 规则 |
|---|---|
| 添加时间 | `createdAt` |
| 购买时间 | `purchasedAt`；没填的永远排在有日期的后面 |
| 修改时间 | `updatedAt` |
| 价格 | `price`；没填的排在有价格的后面 |

方向：每个选项都能切 **新→旧 / 旧→新**（价格则是高→低 / 低→高）。控件显示当前选择，例如 `购买时间 · 新→旧`。

作用范围：

- 分类内衣物网格
- 衣橱首页搜索结果
- 穿搭分类列表、穿搭搜索：只有「添加时间 / 修改时间」（穿搭没有购买价）

分类首页封面：改为该分类按 **添加时间新→旧** 的第一张，不跟列表排序走，避免改资料换封面。

记忆：先记在本次运行内存（Riverpod）。以后再持久化到本地。

## 2. 先详情，再编辑

点击缩略图 → **只读详情**，不再直接进表单。

衣物详情展示：大图、分类、类别、款式、颜色、季节、面料、品牌、价格、尺码测量、购入时间、购买信息、存放位置、标签、备注。空字段显示「未填写」，不要一堆空白框。

顶栏：返回、标题（类别或「单品详情」）、**修改**。删除放在修改页里（和现在一样），详情页不放删除，避免误触。

路由：

```
/wardrobe/item/:id          详情
/wardrobe/item/:id/edit     修改（现有表单）
/wardrobe/item/new          新建（仍直接表单）
```

穿搭同样：

```
/outfits/item/:id
/outfits/item/:id/edit
/outfits/item/new
```

修改保存成功后回到**该单品详情**，不要回到分类网格。
